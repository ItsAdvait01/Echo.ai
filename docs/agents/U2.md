# U2 - Workflow Interpreter and Learner

**Branch:** `agent/U2-workflow-learner`  
**Owner:** Kshitij side (U2 block)  
**Exclusive write paths:** `backend/app/learning/**`  
**Read first:** `docs/PRD.md`, `docs/TRD.md`, `docs/RUNBOOK.md`, `docs/AGENT_RULES.md`.

## 1. U2 responsibility

U2 is the intelligence layer between browser observation (U1) and persistent workflow memory (A2). It does **not** observe the browser, execute actions, persist workflows, or approve workflows.

Its job: receive a normalized `BrowserEvent` stream from U1, distinguish **observed facts** from **inferred intent**, and produce a reviewable `WorkflowDraft` for the user approval layer (A1/A4). U2 may create drafts and submit them for review; only the user/approval layer may mark a workflow approved.

Core principle: **Observation is evidence. Interpretation is an inference. Workflow approval is a user decision.**

## 2. Input event contract (U1 -> U2)

U2 consumes the A1-owned `BrowserEvent` schema in `backend/app/schemas/contracts.py` (single writer: A1; U2 must not modify it):

```text
BrowserEvent:
  id: str
  session_id: str
  timestamp: datetime
  event_type: str
  page_url: str
  page_title: str = ""
  target_summary: str | None = None
  safe_value: str | None = None   # sensitive values already removed by U1
```

`safe_value` is never sent to an LLM and never stored in workflow memory.

## 3. Processing pipeline

Stages are kept logically separate in `backend/app/learning/`:

1. `event_processor.py` — Schema validation, duplicate-id detection, session-id consistency, ordering by timestamp, out-of-order normalization.
2. `event_grouping.py` — Groups related events into activities using page transitions, target descriptors, visible labels and navigation outcomes. Filters safe noise (repeated scrolls, focus/blur/lifecycle events, duplicate consecutive navigations). Preserves meaningful repeated events.
3. `intent_inference.py` — Infers the likely purpose of each group and of the whole stream. Keeps facts and inference separate. Each inference carries supporting event ids, confidence, status, reasoning, and ambiguity.
4. `step_extractor.py` — Converts groups + intent into logical `WorkflowStep`-shaped dictionaries (one step per group).
5. `draft_builder.py` — Assembles the A1-owned `WorkflowDraft`.
6. `validators.py` — Draft validation; enforces draft/review state (never approved).
7. `service.py` — `WorkflowLearnerService`: `generate_workflow_draft`, `validate_workflow_draft`, `submit_workflow_draft`. Orchestrates the pipeline and the A2 handoff.
8. `llm.py` — `LLMProvider` interface plus a mandatory deterministic `RuleBasedFallback`. A real LLM provider can be swapped in; any LLM failure or malformed response falls back to rules.
9. `learner.py` — `WorkflowLearner.create_draft(events) -> WorkflowDraft`, the public entry point.

No multi-agent reasoning, RAG, vector DB, or knowledge graph is introduced inside U2.

## 4. Intent inference rules

- A click alone is weak evidence; page transitions and changed page state strengthen it.
- Each inference includes: inferred intent, supporting event IDs, confidence, inference status, reasoning summary, unresolved ambiguity.
- Inference statuses: `directly_observed`, `supported`, `uncertain`, `incomplete`.
- If a demonstration is too short or ambiguous, U2 produces a draft flagged uncertain/incomplete with clarification notes rather than fabricating a complete workflow.
- Observed facts (target labels, URLs, titles) are stored separately from the inferred intent.

## 5. Event grouping

Events are grouped by page (URL). Within a page visit, the dominant action type and the primary action target are identified. Repeated tiny scrolls and incidental focus/DOM-lifecycle events are dropped; duplicate consecutive navigations to the same page are collapsed. Meaningful repeated actions (e.g. a re-attempt click) are preserved.

Each generated step references its supporting original event IDs (`evidence_event_ids`).

## 6. Workflow JSON schema

U2 conforms to the A1-owned contracts (not redefined independently):

- `WorkflowDraft`: `name`, `description`, `trigger_phrases`, `steps`, `uncertainty_notes`.
- `WorkflowStep`: `id`, `order` (>=1), `action_type`, `target` (dict), `expected_result` (dict), `risk` ("low"/"high").
- `Workflow` (A2 memory model): draft fields plus `id`, `approved` (bool), `created_at`.

U2 maps its richer internal fields (confidence, evidence IDs, inference status, reason, requires_confirmation, preconditions) into each step's `target` and `expected_result` dicts so nothing is lost while staying within the published schema.

Workflow status lifecycle: `draft -> awaiting_review -> approved | rejected`. U2 always leaves the draft unreviewed (`approved=False`); it never approves or persists.

## 7. Confidence model

A simple, deliberately coarse MVP model (`confidence.py`). Scores are rounded to two decimals and are internal estimates, not guarantees. Base confidence per status: `directly_observed` 0.95, `supported` 0.80, `uncertain` 0.55, `incomplete` 0.35, with small dampened adjustments for evidence count, page transitions, and confirmations. A directly observed action and an inferred intent do not receive the same evidence classification.

## 8. LLM integration and fallback

- No API keys or provider are assumed.
- `LLMProvider` interface defines `generate_workflow_proposal(session_id, events) -> dict`.
- `RuleBasedFallback` is the default and always works. It supports: navigation followed by a page transition, opening a course/content item, selecting a lesson, moving to another lesson, and recognizing a visible completion indicator. It is explicitly **not** a general-purpose model.
- If a real LLM provider is configured, it is tried first; any failure or invalid/unusable response falls back to the rules.
- The LLM receives only sanitized event summaries (no `safe_value`, no secrets) and its output is validated through Pydantic before use.

## 9. A2 handoff

A2 owns persistent workflow storage (`backend/app/memory/**`; U2 does not touch it). U2 exposes a clean handoff via `WorkflowLearnerService.submit_workflow_draft(draft, session_id)`, which returns a structured payload:

- `workflow_id`, `status` ("draft"), `approved` (False), `created_at`, `session_id`, `name`, `description`, `version`, `trigger_phrases`, `steps` (with evidence/confidence metadata), `uncertainty_notes`, `handoff_ready`, `requires_user_approval`.

U2 does not implement a second database and does not write into A2's tables. If A2 is unavailable, the service still returns a fully structured in-memory draft result for integration testing.

## 10. API / service interface

Public entry point: `WorkflowLearner.create_draft(events: list[BrowserEvent]) -> WorkflowDraft` (implemented in `learner.py`, delegating to `WorkflowLearnerService`). The service also exposes `validate_workflow_draft(draft)` and `submit_workflow_draft(draft, session_id)`.

Potential A1 routes (to be wired by A1, not U2): `POST /api/learning/process`, `POST /api/learning/draft`, `GET /api/learning/draft/{id}`. U2 does not modify A1 routes.

## 11. Error handling

Structured `WorkflowDraftError` (code, message, details) is raised for: empty streams, invalid/malformed events, duplicate event IDs, mixed sessions, out-of-order handling, ambiguous/insufficient demonstrations, missing page-state evidence, invalid LLM responses, LLM timeouts, invalid workflow JSON, unsupported event types. Nothing important is silently discarded; an incomplete draft is preferred over a fabricated complete one. Drafts are never auto-approved.

## 12. Test instructions

Run from `backend/`:

```
python -m pytest tests/ -v
```

The suite (`tests/test_workflow_learner.py`) covers: valid ingestion, invalid rejection, ordering, duplicate detection, multi-session isolation, grouping, noise filtering, meaningful-event preservation, intent inference, step extraction, evidence IDs, confidence, uncertain intent, empty demonstrations, malformed LLM response, LLM timeout fallback, rule-based fallback, schema validation, draft status enforcement, no auto-approval, and the A2 handoff contract — including the full Python-course navigation demo scenario.

Requires: `pytest`, `pydantic`, `fastapi` (all in `pyproject.toml` dev deps). Lint/format: `ruff check` and `ruff format`.

## 13. Known limitations

- Ordering is by `timestamp`; the published `BrowserEvent` contract has no `sequence_number`, so missing-sequence detection is not applicable beyond timestamp-based ordering.
- Intent inference is a small deterministic rule set plus an optional LLM; it is not a general-purpose model and can mislabel ambiguous targets.
- No semantic workflow similarity or version matching is implemented beyond exact trigger-phrase/name cues (deferred per P2 priority).
- Persistence and approval are owned by A2/A1; U2 never saves or approves.
